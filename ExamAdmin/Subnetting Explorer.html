Twisted Pair Cable (STP vs UTP)

Twisted pair cabling is extensively used for computer networks. Wires are twisted together to cancel out electromagnetic interference (EMI).

FeatureUnshielded Twisted Pair (UTP)Shielded Twisted Pair (STP)
Description Pairs of wires twisted together without shielding. Enclosed in a metallic shield or foil to reduce EMI.
Cost & Installation Cheaper, flexible, highly widely used. More expensive, bulkier, requires grounding.
Environments Offices, homes, standard networks. Industrial environments with high electrical noise.

EncodingDescription
NRZ (Non-Return to Zero)Voltage indicates bit value (e.g., high = 1, low = 0). No neutral/rest state. Simple but lacks self-clocking, leading to baseline wander over long runs of 0s or 1s.
ManchesterA voltage transition happens in the middle of each bit period (e.g., high-to-low for 1, low-to-high for 0). This transition provides self-synchronizing clocking. Traditionally used in 10Base-T Ethernet.
Differential ManchesterA mid-bit transition exists for clocking. Data is encoded by the presence or absence of a transition at the beginning of the bit period. More complex but robust against signal inversions.

Fiber TypeDescription
Single-mode Fiber (SMF)Features a very narrow core (approx. 8–10 microns). Light travels in a nearly single straight path, eliminating modal dispersion. Ideal for high-bandwidth, long-distance WANs. Typically propelled by lasers.
Multimode Fiber (MMF)Has a wider core (approx. 50–62.5 microns). Light can bounce through the core in multiple angles (modes). Subject to modal dispersion over long distances. Suitable for shorter links (LANs, data centers) and often uses LED or VCSEL light sources.

MAC Frame Structures
IEEE 802.3
Ethernet Frame

Uses CSMAC/CD. The typical frame contains:

Preamble (7) | SFD (1) | Dest MAC (6) | Src MAC (6) | Length/Type (2) | Data (46-1500) | FCS (4)
IEEE 802.5
Token Ring / FDDI Frame

Token ring networks use token passing to control access.

SD (1) | AC (1) | FC (1) | Dest MAC (6) | Src MAC (6) | Data | FCS (4) | ED (1) | FS (1)
SDLC / HDLC
Synchronous Data Link Control

Uses start/end flags for frame delineation and bit-stuffing.

Flag (01111110) | Address (1-2) | Control (1-2) | Info | FCS (2-4) | Flag (01111110)
Frame Delineation & Bit Stuffing

In HDLC/SDLC, the flag `01111110` indicates the start and end of a frame. To prevent this pattern appearing in the data payload, bit stuffing is used:

Sender adds a 0 bit after every five consecutive 1 bits in the data stream. The receiver reverses this by removing the 0 bit after five 1s.

Error Detection vs Correction

Error Detection adds redundancy (e.g. Parity bit, Checksum, CRC) to determine if a frame was corrupted. If an error is detected, the frame is discarded and retransmission is requested.

Error Correction (Forward Error Correction - FEC) adds more redundancy (e.g. Hamming Code) so the receiver can locate and correct the error without requesting retransmission.

Why do wireless networks favour Error Correction?
Wireless links are highly prone to noise, interference, and fading, leading to high bit error rates. If they used detection-only, continuous retransmissions would cripple throughput. Error correction allows the receiver to recover lost data on the fly.

TCP Sequences & Window Flow Control

TCP provides reliable, ordered data delivery. A critical mechanism is sliding window flow control.

  • SEQ (Sequence Number): Identifies the first byte of data in this segment's payload.
  • ACK (Acknowledgment Number): The next byte the sender of this segment expects to receive (cumulative ACK).
  • WIN (Window Size): The amount of free buffer space the sender of this segment has available. It tells the other side "you can send me up to this many bytes".
  • LEN (Payload Length): The number of application bytes in the TCP segment.
