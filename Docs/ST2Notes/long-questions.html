Expected Long-Question Structure

What the paper is likely to look like, and why the longer questions tend to be calculation-heavy rather than essay-heavy.

The guide predicts a paper with 25 marks of multiple choice and 25 marks of longer questions, probably split across four longer questions in a 90-minute test.

Past papers suggest the longer questions are usually short, mark-splittable tasks rather than pure theory essays. The most common forms are calculations, table completion, structured protocol explanations, encoding questions, and "list any five" style answers.

  • Subnetting works well because every intermediate value can earn marks.
  • Routing algorithms work well because iterations or updates can be marked step by step.
  • TCP timers and TCP reliability work well because each mechanism can be awarded separately.
  • QUIC and ASN.1 fit nicely as compact explanation or structure-definition questions.

Worked Topic

IPv4 Subnetting, CIDR, And Supernetting

The most likely calculation topic, including the full `/26` walkthrough, supernetting logic, longest-prefix match, and common traps.

Why this is highly likely

Subnetting naturally breaks into parts such as subnet mask, network address, broadcast address, usable hosts, supernet choice, and routing-table matching. That makes it one of the cleanest long-question topics to mark.

Core formulas

host bits = 32 - prefix length
total addresses = 2^(host bits)
usable hosts = 2^(host bits) - 2
CIDRMaskBlock sizeUsable hosts
/24255.255.255.0256254
/26255.255.255.1926462
/27255.255.255.2243230
/30255.255.255.25242
/22255.255.252.04 in the third octet1022

Full worked example: 170.170.42.150/26

  1. Convert /26 to a mask: 255.255.255.192.
  2. Find the block size: 256 - 192 = 64.
  3. List final-octet ranges: 0-63, 64-127, 128-191, 192-255.
  4. Locate 150: it falls in 128-191.
  5. So the network is 170.170.42.128/26.
  6. The broadcast address is the end of that range: 170.170.42.191.
  7. The first usable host is 170.170.42.129.
  8. The last usable host is 170.170.42.190.
  9. Host bits are 32 - 26 = 6, so usable hosts are 2^6 - 2 = 62.

Supernetting example

For the range 41.32.0.0 to 41.39.255.255, the second octet spans 32 to 39. In binary that range shares the prefix 00100xxx, which gives 5 fixed bits in the second octet. Add the 8 fixed bits from the first octet and you get a /13 prefix.

Answer: 41.32.0.0/13

Longest-prefix match

10.10.10.0/24    next hop A
10.10.0.0/16     next hop B
10.0.0.0/8       next hop C
0.0.0.0/0        next hop D

For destination 10.10.1.2, the best route is 10.10.0.0/16 because it is the longest matching prefix among the valid matches.

Common traps

  • /26 means 26 network bits, not 26 hosts.
  • Usable hosts usually require subtracting 2 for network and broadcast.
  • Do not pick the first matching route; pick the most specific matching route.
  • 0.0.0.0/0 is the default route, not "no route".
  • The broadcast address is the final address in the subnet, not the last usable host.

Routing Algorithms

Dijkstra and Bellman-Ford / RIP in the exact table-driven style these questions usually use.
Protocol / conceptAlgorithmExchange styleKey issue or feature
OSPFDijkstraLink-state / topology informationEach router builds a map and computes shortest paths.
RIPBellman-FordDistance vectors / routing tablesCounting to infinity can occur.
BGPPath-vector styleInter-AS route exchangeExternal gateway protocol.

Dijkstra method

  1. Set the source to cost 0 and every other node to infinity.
  2. Finalise the source.
  3. Update costs to neighbouring nodes.
  4. Pick the unfinished node with the lowest current cost.
  5. Repeat until all required nodes are finalised.

Dijkstra worked example from A

A-B: 1
B-E: 1
E-F: 2
E-D: 3
D-C: 1
B-C: 6
A-F: 10
StepPicked nodeImportant update
InitialAB = 1, F = 10
1BE = 2, C = 7
2EF improves to 4, D = 5
3FNo better update
4DC improves from 7 to 6
5CFinished

Final shortest path to C is A-B-E-D-C with total cost 6.

Trap: the predecessor of C is D, but the next hop from A to C is B.

Bellman-Ford / RIP update rule

new cost via neighbour = cost to neighbour + neighbour's advertised cost

If router D reaches C at cost 3 and C advertises destination A at cost 7, then D can reach A via C at cost 10.

Counting to infinity

This is specifically associated with Bellman-Ford / RIP. A router may have to adopt a worse cost if the update comes from its current next hop, which is exactly how costs can keep increasing after a failure.

TCP Reliability Mechanisms

The high-value "list and briefly explain five" topic, plus the common ACK and phantom-byte traps.

A strong answer to "TCP is reliable. List and briefly explain five mechanisms" can be built from the following pool:

MechanismShort explanation
3-way handshake to establishChecks that both endpoints are alive and both directions work before data transfer begins.
Sequence numbersAllow missing, duplicated, or out-of-order bytes to be detected.
Acknowledgement numbersTell the sender which byte the receiver expects next.
ACK-based ARQIf data is not acknowledged, TCP retransmits it.
Retransmission timerDrives retransmission when acknowledgement does not arrive in time.
Sliding window / window advertisementSupports flow control so the sender does not overwhelm the receiver.
ChecksumDetects segment corruption.
Slow startPrevents the sender from injecting too much traffic too quickly.
Exponential back-offSpaces out retransmissions more aggressively under repeated loss.

3-way handshake

A -> B: SYN
B -> A: SYN + ACK
A -> B: ACK

The SYN and SYN+ACK each consume a sequence number even though they do not carry real payload data. These are the so-called phantom bytes. The final ACK does not consume one.

ACK flag trap

If the acknowledgement field contains a value like 150 but the ACK flag is not set, the number has no meaning and must be ignored.

Useful header fields to memorise

Source Port, Destination Port, Sequence Number, Acknowledgement Number, Window, Checksum, Urgent Pointer, Options, Padding, and Flags. A common distractor is Length, which is not a standard TCP header field.

TCP Timers

The direct memo-style timer question with the exact "what happens when it expires" framing.
TimerWhat happens when it expiresWhy it matters
RetransmissionUnacknowledged data is sent again.Handles loss and damaged segments.
AcknowledgementAn ACK is sent.Supports delayed acknowledgements and piggybacking.
PersistenceA probe is sent.Checks whether the receiver's window has opened again.
KeepaliveProbe messages are sent.Checks whether the peer is still alive.
QuietThe wait period ends and resources or port usage can be released.Prevents old traffic from colliding with a new connection.

Timer traps

  • Persistence sends a probe, not normal retransmitted data.
  • Keepalive is about peer liveness, not congestion control.
  • Quiet applies after closing, before safe reuse of the connection context.
  • Retransmission and acknowledgement timers do different jobs: one resends data, the other sends an ACK.
Calculation

TCP Window And ACK Calculations

The byte-counting logic behind sequence numbers, acknowledgement numbers, and advertised windows.

Key meanings

  • The sequence number identifies the first byte in a segment.
  • The acknowledgement number says "I have received everything up to ACK minus 1, and I next expect ACK".
  • The advertised window is roughly remaining receive-buffer space.

Mini example

If a segment starts with sequence number 500 and contains 100 bytes, then it covers bytes 500 to 599, so the receiver will acknowledge with 600.

Worked window example

A receiver has a 1000-byte buffer. It has accepted bytes 1 to 400, but the application has only consumed bytes 1 to 150.

  1. Next expected byte is 401.
  2. Unconsumed bytes are 151 to 400, which is 250 bytes.
  3. Advertised window is 1000 - 250 = 750.
Layer 4

QUIC

Why QUIC is called quick, what it inherits from UDP, and the exam-ready talking points for comparison questions.

Core facts

  • QUIC runs over UDP.
  • It integrates transport and encryption setup more tightly than TCP plus TLS.
  • It supports multiple independent streams in one connection.
  • It supports client-initiated connection migration using connection IDs.

Why QUIC is "quick"

  1. It reduces setup latency with 1-RTT establishment.
  2. It can sometimes send data immediately on repeat connections using 0-RTT.
  3. It supports multiplexed streams, so one delayed stream does not necessarily stall everything else in the same way as a single TCP stream.
  4. It can survive client IP changes through connection migration instead of full reconnection.

Exam-ready answer

QUIC reduces latency by reducing round trips before useful data can be exchanged, supporting 0-RTT and 1-RTT establishment, multiplexing multiple streams, and allowing client-initiated connection migration via connection IDs. It is quick because it reduces waiting time, not because it increases raw physical bit rate.

ASN.1

The likely Layer 6 long-question option, including constructors, BER, and a full declaration example.

ASN.1 stands for Abstract Syntax Notation One. It defines the structure of protocol messages, while encoding rules such as BER define how those structures are represented as bytes.

BER

BER = Type, Length, Value

If the exam asks what a BER triple contains, the answer is simply type, length, and value.

Invalid distractors to reject

  • STRUCT
  • ARRAY
  • MESSAGE

Worked ASN.1 declaration

Student ::= SEQUENCE {
  surname        VisibleString,
  initials       VisibleString,
  studentNumber  INTEGER,
  courses        SET OF Course,
  address        Address
}

Course ::= SEQUENCE {
  code        VisibleString,
  courseName  VisibleString,
  mark        INTEGER
}

Address ::= CHOICE {
  streetAddress  StreetAddress,
  poBoxAddress   POBoxAddress
}

This works because the student record is a structured record, courses repeat, and the address is one of two alternatives.

Supporting Topics

Shorter structured topics that may appear as smaller long-question parts or important MCQ support material.

IPv6 essentials

IPv6 uses 128-bit hexadecimal addresses. You can remove leading zeroes in each group and replace one consecutive run of zero groups with ::, but only once.

2001:0db8:0000:0000:0000:ff00:0042:8329
-> 2001:db8::ff00:42:8329

ARP and ICMP

ARP maps an IPv4 address to a local MAC address. If the destination is remote, the host ARPs for the default gateway's MAC address, not the final host. TTL is decremented at each router, and when it reaches zero the router discards the packet and may send an ICMP Time Exceeded message.

Packet forwarding rule

Routers check for direct delivery first, then routing-table matches, then a default route. If multiple routes match, the longest matching prefix wins.

Layer 5 session ideas

The Session Layer is associated with checkpoints, rollback or recovery, long-lived sessions, and heartbeat-style liveness checks.

  • I can run a Dijkstra trace.
  • I can update a routing table using neighbour advertisements.

  • I know the 3-way handshake and phantom-byte rule.
  • I know the ACK field is meaningless without the ACK flag.
  • I can list TCP header fields.
  • I can explain five reliability mechanisms.
  • I know all five TCP timers.
  • I can calculate basic ACK and window values.

QUIC and ASN.1

  • I know QUIC runs over UDP and reduces latency.
  • I know QUIC supports 0-RTT, 1-RTT, multiplexing, and migration.
  • I know BER means type-length-value.
