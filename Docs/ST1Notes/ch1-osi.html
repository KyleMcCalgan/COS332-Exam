1.0 History & Context

Proprietary protocols: Early networks used proprietary protocols owned by specific vendors. A company had to buy all equipment from one vendor, preventing interoperability between different networks.

The Cold War was a major driving force for ARPAnet's design — the goal was to build a decentralised, survivable network that could function even if portions were destroyed.

OSI vs. TCP/IP: The ISO OSI model was intended to be the universal standard to replace proprietary networks. It failed in practice because TCP/IP matured first and became so widely deployed that implementing the complex OSI model was no longer practical. Today, OSI serves strictly as an educational and reference model.

1.1 Introduction

ISO is NOT an acronym — it is derived from the Greek word îsos, meaning "the same" (as in isomorphic). The idea: a standard makes products "the same" and compatible worldwide. OSI = Open Systems Interconnection.
  • Protocol: A set of conventions — a detailed, agreed-upon description of rules to follow when communicating.
  • Protocol stack: Protocols are literally stacked in layers to separate and manage functionality.
  • As a message moves down the protocol stack towards the physical layer, headers are added (appended) at each layer.
Dæmon: The software providing services on the Internet (acting as a server waiting for client requests) is often known as a dæmon. To serve in client-server architecture, it must open a socket specifying an address and port number, and wait for connections.

1.2 The Seven Layers

Each layer provides services to the layer above it and uses services from the layer below. Each layer communicates logically with its peer layer at the destination, but physically only with adjacent layers.

If Node X communicates with Node Z, a header added at layer n at Node X will be removed by layer n at Node Z.
Layers 1–4 = Network-oriented layers. Layers 5–7 = Application-oriented layers.

Layer 7 — Application Layer

Contains the network protocols that directly support end-user applications. The WWW fits on Layer 7.

  • Application software is NOT the application layer — only the network-interacting part is.
  • A single application can use multiple protocols (e.g. an email client uses SMTP and POP3).
  • Examples: HTTP, SMTP, POP3, FTP, DNS.
  • Should NOT deal with routing, media, or physical details — those are delegated downward.
  • Example header field added at L7: the HTTP GET method type.
  • Note: SMTP, POP3, and FTP are L7 protocols but inherently include L6 and L5 functionality.

Layer 6 — Presentation Layer

Positioned exactly between the Session and Application layers. Deals with data representation, character code translation, compression, and encryption.

  • Think of it as a codec: translates local character encodings (ASCII, EBCDIC, Fieldata) into a universal network format and back again.
  • Also handles semantic representations like translating date formats between cultures.
  • In modern networks, often absorbed directly into L7 application protocols.
  • Example header field added at L6: UTF-8 (or any character encoding).
Encryption trap: On which layer should encryption be placed? Answer: it depends — all layers from 3 to 7 are options depending on whether you want link, transport, or application-level encryption. The easy answer is Layer 6, but this is context-dependent.

Layer 5 — Session Layer

Positioned exactly between the Transport and Presentation layers. Establishes, maintains, and terminates sessions. Enforces dialogue control.

  • Inserts synchronisation points (checkpoints) into long transactions — only messages since the last checkpoint must be retransmitted after a dropped connection.
  • Attempts to emulate database transactions: messages can be "rolled back" if the final message in a sequence isn't successfully sent.
  • In practice, usually merged into the application layer.
"Who transmits next" trap: Which layer regulates which node may transmit next when two computers are directly connected? Answer: Layer 2 OR Layer 5, depending on factors not mentioned — L2 handles physical media access; L5 handles it logically via dialogue control.

Layer 4 — Transport Layer

Enables process-to-process (end-to-end) communication via a logical "pipe" between processes across the network.

  • Reliable (connection-oriented): handles retransmissions, error correction, congestion control. Example: TCP.
  • Unreliable (connectionless): best-effort, faster — used where speed > perfection (live voice/video). Example: UDP.
  • Example header field added at L4: Port Address.

Layer 3 — Network Layer

Responsible for routing packets across multiple network hops.

  • Routers are technically called multihomed hosts — computers with multiple interfaces connecting different networks.
  • Routing tables: routers use these to determine the next hop for each destination address.
  • Source routing: the packet includes the full route — rarely used, mainly for diagnostics.
  • Example header field added at L3: IP Address.
Peer trap: If Node X sends to Node Y, which node's L3 is the peer of X's L3? Answer: All nodes on the path from X to Y — every router processes the L3 header to route the packet.

Layer 2 — Data Link Layer

Gets a message from one hop to the next across a direct physical connection. Three primary functions:

  1. Media Access Control (Contention Control): Prevents multiple nodes transmitting simultaneously on a shared medium.
  2. Data Delineation: Marks the start and end of a message in a continuous bit stream.
  3. Error Control: Uses checksums/CRC to detect (and sometimes correct) transmission errors.

Examples: Ethernet, HDLC, Token Ring. Example header field added at L2: MAC Address.

L1 impact on L2: A noisy L1 medium requires error correction on L2; a good L1 medium only needs error checking on L2.

Layer 1 — Physical Layer

Deals with the physical medium (copper, fibre, radio), bit representation, plugs, multiplexing, and signal attenuation.

⚠ Exam Traps

Standards are NOT binding. If ISO or IEEE adopts a standard, no country or organisation is required to comply. Standards may only be mandated by external processes (e.g. government laws or market dominance).
Error checking happens on ALL 7 layers. Every layer has its own form of error checking — L2 for frame transmission errors, L3 for routing loops, L4 for missing segments, L6 for malformed data, L7 for 404/application errors. The answer is NOT just "Layer 2".
Header field examples per layer:
L7: GET method type  |  L6: UTF-8 encoding  |  L4: Port address  |  L3: IP address  |  L2: MAC address

Memo / Answer Key

MCQ Answers

A1. B (Proprietary = owned by a specific vendor).
A2. A (Cold War — ARPAnet was designed to survive nuclear attack).
A3. C (Wait for connections; a server does not initiate). (The socket must also be specified as address+port, but the defining action is waiting.)
A4. A (Protocols are stacked in layers on top of one another).
A5. D (Layer 5 — the session layer provides transaction-like rollback).
A6. E (It may be Layer 2 for media access control, or Layer 5 for dialogue control — depends on context).
A7. B (Layers 6 and 5 — SMTP, POP3, FTP all include presentation and session functionality).
A8. D (Standards are not binding; no country must comply).
A9. C (Segment is the transport layer data unit).
A10. D (Layer 2 — the data link layer adds the MAC address).

Long-Form Answers

A11. Layer 2 functions.

  • a) Media Access Control (contention control): Determines which node may transmit when multiple nodes share a medium (e.g., Ethernet CSMA/CD).
  • b) Data delineation: Marks the start and end of a frame in a continuous bit stream so the receiver knows where one frame ends and the next begins.
  • c) Error control: Checksums (e.g., CRC) are added so the receiver can detect (and sometimes correct) transmission errors.

Impact of noisy Layer 1: A noisy medium requires error correction at Layer 2 (e.g., FEC — forward error correction), whereas a clean medium only needs error detection (simpler checksums, with retransmission on error).

A12. Header fields per layer.

  • Layer 7: GET (HTTP method) / EHLO (SMTP command)
  • Layer 6: UTF-8 (character encoding) / base64 (Content-Transfer-Encoding)
  • Layer 4: Source Port / Destination Port
  • Layer 3: Source IP Address / Destination IP Address
  • Layer 2: Source MAC Address / Destination MAC Address

A13. Peer layers.

  • (i) Layer 7 peer of X: Only node Z. Routers R1 and R2 do not process Layer 7 headers — they only process up to Layer 3 to route the packet.
  • (ii) Layer 3 peers of X: R1, R2, and Z — every node along the path must inspect the Layer 3 (IP) header to make routing decisions, so all of them are Layer 3 peers.
