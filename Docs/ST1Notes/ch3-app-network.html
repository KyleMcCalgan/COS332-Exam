3.2 DNS — Domain Name System

Translates (strictly speaking, resolves) human-readable domain names into IP addresses. Replaced the old centralised /etc/hosts file approach (which didn't scale).

DNS normally operates on port 53. It uses both TCP and UDP: UDP for standard fast lookups, TCP for larger tasks like zone transfers.
The popular server software used as a name server is known as bind. The 'd' in bind stands for dæmon.

Domain Hierarchy & TLDs

DNS uses a hierarchical namespace with the principle of local autonomy: authority over a subtree can be delegated independently. If a group wants to establish a new TLD, ICANN is the body that must approve it.

ccTLD (country-code).za (South Africa), .bw (Botswana), .ls (Lesotho), .io.io is a ccTLD (British Indian Ocean Territory). Domain hacking: who.is uses .is (Iceland).

Zone File Example & Key Details

$TTL 7200
@ IN SOA ns1.example.com. admin.example.com. (
    2026031801 ; serial (YYYYMMDDnn format)
    3600       ; refresh
    1800       ; retry   ← seconds secondary waits after failed sync
    3600000    ; expire
    3600 )     ; minimum TTL

www  IN A    192.168.18.59
mail IN A    192.168.18.59
@    IN NS   ns1.example.com.
@    IN MX 10 mail          ← priority 10 = preferred
@    IN MX 20 mail.example.com.  ← priority 20 = fallback
ftp  IN CNAME www

Key zone file details:

  • @ symbol matches the domain name itself (e.g. routes example.com rather than www.example.com).
  • Serial format: YYYYMMDDnn. Example: serial 2001102002 was created on 20 October 2001 (nn = the 2nd change that day).
  • RETRY field: seconds a secondary nameserver waits before retrying after a failed synchronisation attempt.
  • Zone transfer: the process of copying DNS entries from a primary server to a secondary server. Uses TCP.
  • TTL: controls how long clients cache DNS responses before refreshing.
  • Non-authoritative answer: served from cache rather than directly from the authoritative server.
  • Reverse DNS: uses the in-addr.arpa domain. Address is reversed: 4.3.2.1.in-addr.arpa resolves the PTR for 1.2.3.4.

Glue Records & CNAME Restrictions

Glue Record: When an NS record points to a subdomain of the same zone (e.g. ns1.up.ac.za for the up.ac.za zone), the parent zone must also provide an A record for that nameserver. This "glue" prevents a circular dependency — otherwise you'd need the IP of the server to ask the server for its own IP.
CNAME restriction: A CNAME record must always point to another domain name — never directly to an IP address. Furthermore, MX records should never point to a CNAME; they must point to an A or AAAA record.

Name Resolution: Recursive vs Iterative

Demo — DNS Resolution Simulator
  • Recursive: The DNS server behaves like a personal assistant — does all the legwork and only returns the final answer (the IP) to the client.
  • Iterative: The DNS server behaves like a receptionist — says "I don't know, but ask that server" and provides a referral pointer. Root servers strictly use this method to avoid being overloaded.

In practice: client sends a recursive query to the ISP/corporate nameserver, which internally uses iterative queries to root and TLD servers.

13 root name servers: a.root-servers.net through m.root-servers.net. Their addresses are hardcoded into DNS software.

If the FQDNs of DNS root name servers are ordered lexicographically, the last entry is m.root-servers.net.
Root server trap: Root name servers do NOT perform iterative, recursive, or non-authoritative name resolution — they merely return referrals/NS pointers to other servers. The bulk of resource records in root name servers are of type NS.

Zone File Tracing Logic (Exam Walkthroughs)

Iterative tracing: If a name server is strictly iterative and only has an NS record for a domain, asking it for an A or MX record will yield N/A (no address returned). You must follow the NS pointer to the next server.
A command like set type=NS followed by com. specifically asks for the NS record of the com. TLD.

nslookup tools: nslookup (Windows), dig (Linux). Use server <ip> inside nslookup to change the nameserver used.

3.3 Bootstrapping Protocols

DHCP (Dynamic Host Configuration Protocol): Used when computers boot to obtain configuration automatically.

  • Provides: IP address (with lease), default gateway, DNS server addresses, SMTP server addresses.
  • For diskless computers: also provides address of network boot image (loaded via TFTP).

TFTP (Trivial File Transfer Protocol): Very simple protocol used to retrieve files via the network. The protocol a diskless computer uses to transfer an OS image from a server at boot. Uses UDP.

3.4 Network Management Protocols

SNMP — Simple Network Management Protocol

Most popular network management protocol. Uses variables to represent network state/config.

An SNMP agent is BOTH a client and a server — it pushes Traps as a client, and accepts Get/Set configuration reads/writes as a server. ("More than one of the above" in MCQs.)
Manager → Agent (polling)
GetRetrieve a variable's value
GetNextRetrieve next variable
GetBulkRetrieve multiple variables
SetChange a variable's value
Agent → Manager (alerts)
TrapPush critical alert (no acknowledgement expected)
InformLike Trap but expects acknowledgement

CMIP — Common Management Information Protocol

ISO OSI counterpart to SNMP. More powerful; primarily used in telecommunications. CMOT = CMIP over TCP/IP. Managed entities = Network Elements (NEs); management system = Element Management System (EMS). SNMP, CMIP, and CMOT are all valid network management protocol examples.

3.5 Directory Access Protocols

X.500

OSI standard for directory services (introduced by the CCITT). Organises data in a Directory Information Tree (DIT).

ComponentRole
DSADirectory System Agent — manages the tree/subtree
DUADirectory User Agent — queries the DSA
DAPDirectory Access Protocol (DUA↔DSA)
DSPDirectory Systems Protocol (DSA↔DSA)

Distinguished Name (DN): Unique path in the DIT, e.g. {C=ZA, O=SANDF, OU=Air Force, CN=Col Burger}

X.509 — Public Key Certificates

Part of the X.500 series. Implements a public key infrastructure (PKI) for encryption purposes.

OperationKeys UsedPurpose
Encrypt for confidentialityRecipient's public keyOnly recipient can decrypt (with private key)
Sign for authenticationSender's private keyAnyone can verify with sender's public key
Both confidential + signedRecipient's public + sender's privateConfidential AND authenticated

Certificate Authorities (CAs): Trusted third parties who sign public keys. Certificate chain: User cert → intermediate CA → root CA. Root CAs are pre-trusted (built into browsers).

Mark Shuttleworth founded Thawte (SA) — one of the first trusted CAs in browsers. Later acquired by VeriSign.

LDAP — Lightweight Directory Access Protocol

Simplified version of X.500 DAP. Widely used for authentication and directory services (e.g. Microsoft Active Directory). Enables single sign-on.

  • Base DN uses X.500 notation (c=ZA, o=Example) or DNS components (dc=example, dc=za).
  • LDIF (LDAP Data Interchange Format, RFC 2849): standard format for migrating LDAP data between servers.

Dijkstra's Algorithm (used by OSPF)

Characteristics: Greedy, static/non-adaptive, centralised. Finds shortest paths from a single source to all nodes.

  1. Start: put source in 'Done' set. Record cost and predecessor for each neighbour.
  2. Greedy selection: from 'Candidates', pick the node with lowest known total cost from source → move to 'Done'.
  3. Update: for each unvisited neighbour of the newly added node, if new path cost < current known cost, update.
  4. Repeat until all nodes are in 'Done'. Evaluate neighbours of the entire finalised set to find the absolute cheapest next step.

OSPF — Open Shortest Path First (IGP)

  • Each router stores the entire network topology as a Link-State Database (LSDB).
  • LSDB is flooded to all routers — all routers broadcast their version of the network topology.
  • Each router independently runs Dijkstra's algorithm on the LSDB.
  • Only sends LSDB updates when topology changes — more efficient than RIP's periodic full broadcasts.
  • Networks divided into areas; border routers summarise area info for inter-area efficiency.

Bellman-Ford Algorithm (used by RIP)

Characteristics: Distributed, adaptive. Can handle negative edge weights (unlike Dijkstra).

Each router maintains a routing table: ⟨destination, next-hop, cost⟩. Routers exchange tables and update their own. If router r1 receives from r2 that r2 can reach destination d in h hops, then r1 knows it can reach d in h+1 hops via r2.

'Count to infinity' problem: Bellman-Ford suffers from this — when a link goes down, nodes may slowly increment cost toward infinity before converging. This is Bellman-Ford's distinguishing weakness.

RIP — Routing Information Protocol

Implements Bellman-Ford. Uses hop count as metric (max 15 hops; 16 = infinity = unreachable).

  • Routers periodically broadcast/multicast their routing tables.
  • Any receiving router knows it is 1 hop away from the broadcasting router.
  • Easy to deploy: no manual configuration needed — starts learning immediately.
RIP cost calculation (exam question): If router r sends its routing table to router s, and r says it can reach network n at a cost of 5 — what is the cost from s to n? Answer: 6 (cost from r to n + the 1 hop from s to r).
Security concern: An intruder could broadcast false short routes to redirect traffic.

⚠ Exam Traps

Root servers use iterative only — they return NS referrals; they do not recursively resolve names or return non-authoritative answers.
SNMP agent = client AND server. It pushes Traps (client) and responds to Get/Set (server). Answer is "more than one of the above".
BGP is the EGP example. RIP and OSPF are IGPs. BGP operates between autonomous systems and makes decisions based on policies, not cost.
DNS port 53 uses both TCP and UDP — UDP for standard lookups, TCP for zone transfers. Don't say just one.
tech.za does not exist. nom.za is for individuals. .co.za registration requires no SA citizenship.

Long-Form Answers

A14. Zone file:

@ A 41.203.18.59
www CNAME xx.co.za.
@ MX 5 ASPMX.L.GOOGLE.COM.
@ MX 10 ALT1.ASPMX.L.GOOGLE.COM.
@ NS ns1.host-h.net.
@ NS ns2.host-h.net.
abc NS ns1.host-h.net.
abc NS ns2.host-h.net.
@ AAAA 2001::1234
@ HOST Raspberry Pi

Note: www CNAME xx.co.za. (with trailing dot) creates the alias without a separate A record, so only @ A needs updating if the IP changes.
