2.2 Network Architectures

The application layer is the raison d'être (reason for existence) of the network. The way services are arranged is called the network architecture.

The most prominent architecture. Servers listen for and accept orders from clients (like a restaurant waiter). The client always initiates communication.

  • Server software runs continuously as a dæmon (e.g. ftpd, httpd).
  • To serve as a server, the application must open a socket that waits for connections.
  • Limitation: because the client always initiates, workarounds are needed when a server must notify a client.

Nodes are peers — equals that can both initiate communication. No fixed server role.

  • Napster: early file-sharing P2P network — the classic exam example. Failed when Napster's index server was shut down; later P2P systems made the index distributed too.
  • MANETs (Mobile Ad-hoc Sensor Networks): used in natural disasters where battery-powered nodes must dynamically configure themselves without a central server.
Do NOT confuse P2P peers with 'peer layers' in the OSI model — different concept.

Extends client-server into more layers. Common is 3-tier: client tier → server tier → back-end (database) tier. Separates business logic from data storage.

2.3 Email Protocols

X.400

ITU-T/OSI standard for email (Message Handling System). Designed to integrate with postal delivery. Address format uses: C (Country), ADMD, PRMD, O (Organisation), OU, G/I/S (Given/Initials/Surname).

Example: I=J;S=Doe;O=acme;OU=sales;A=sapo;C=za

Still used today in EDI (Electronic Data Interchange) for structured business documents.

SMTP — Simple Mail Transfer Protocol (RFC 5321)

The dominant email transfer protocol. Uses Mail Transfer Agents (MTAs) and Mail User Agents (MUAs).

PortUse
25MTA-to-MTA (server-to-server). If SMTP server X forwards to server Y, server Y uses port 25.
587Submission port — MUA to MTA (user submitting to first MTA).

Key commands & details:

  • EHLO / HELO — greeting from client. After a successful EHLO/HELO, the server returns condition code 250.
  • MAIL FROM: <address> — identify sender
  • RCPT TO: <address> — to send to u@xx.co.za, the command is RCPT TO: u@xx.co.za
  • DATA — begin body. Payload ends with a line containing only a full stop (.)
  • QUIT — end session

Header vs body: An email consists of a header and a body, separated by a blank line.

Transparency / dot-stuffing: The body ends when the client sends a full stop on a line of its own. Users should technically avoid this in email body text — but modern clients use "dot-stuffing" (prefixing a lone . with another .), making it practically safe.
SMTP was not designed with security in mind — no built-in authentication for sending.

POP3 — Post Office Protocol v3 (RFC 1939)

Retrieves email from a mail server to the user's local machine. Assumes users manage mailboxes locally. Port 110.

S: +OK POP3 server ready
C: USER alice
S: +OK
C: PASS secret
S: +OK mailbox locked and ready

Also supports APOP (challenge-response authentication).

C: STAT          → S: +OK 3 4321  (3 messages, 4321 bytes)
C: RETR 1        → S: +OK [message text]
C: DELE 1        → S: +OK message 1 marked for deletion
C: QUIT          → S: +OK (deletions now executed)
Deletions are only performed at QUIT. Not suitable for multiple devices — messages are downloaded and removed from the server.

IMAP4 — Internet Message Access Protocol v4

Unlike POP3, IMAP4 is primarily intended to manipulate a mailbox on the server. Users manage complex folder structures remotely, set flags, and fetch specific parts of an email. Port 143.

CommandPurpose
LOGINAuthenticate
SELECT folderOpen a folder
FETCH n BODYRetrieve message or specific part (BODY.PEEK, ENVELOPE, FLAGS)
STORE n +FLAGS (\Seen)Set flags
EXPUNGEPermanently delete \Deleted messages
LOGOUTEnd session

Flags: \Answered, \Flagged, \Deleted (soft-delete until EXPUNGE), \Seen, \Draft.

2.4 Virtual Terminal Protocols

Telnet

One of the oldest virtual terminal protocols. The specific service offered by Telnet is a virtual terminal. Port 23.

Major security flaw: username and password transmitted as cleartext. Anyone who can eavesdrop sees them.
ConceptDetail
Escape characterThe client displays a character combination (^] i.e. Ctrl+]) to open the Telnet console. This is called the escape character.
localechoBy default, the remote server echoes back what you type. If you can see output but cannot see what you type, adjust localecho with set localecho in the client shell.
Manual HTTP testTo interact with www.example.com using HTTP manually: telnet www.example.com 80

ANSI escape sequences (used for terminal formatting):

SequenceEffect
ESC[2JClear screen (ESC = ASCII 27 decimal)
ESC[HMove cursor to top-left
ESC[y;xHMove cursor to row y, column x

Java example — print "Hello" on line 5 at position 20: screen.write(27); screen.print("[20;5HHello");

Non-traditional use: Because many application layer protocols exchange simple character strings, a Telnet client is an invaluable tool for manually testing any text-based server: telnet www.example.com 80, then type HTTP commands. Use set localecho to see what you type.

SSH — Secure Shell

The secure, encrypted alternative to Telnet. Port 22 — requested by creator Tatu Ylonen specifically to sit between FTP (21) and Telnet (23).

  • Multiple authentication methods: password, public key, etc.
  • Used as a tunnelling protocol (e.g. for X.11 window system).
  • scp for secure file transfers.

FTP — File Transfer Protocol (RFC 959)

Used for transferring files. Anonymous FTP allows public access using username anonymous or ftp. Key feature: two separate connections.

Demo — FTP Active vs Passive Mode

Data (Active/PORT)20Server connects FROM port 20 back TO client. Fails behind firewalls.
Data (Passive/PASV)randomServer opens random port; client connects. Bypasses client firewall issues. Modern standard.

Client commands: get, mget, put, mput, lcd, cd. Protocol commands: RETR (retrieve), STOR (store).

2.5 The Web — HTTP, HTTPS & CGI

HyperText Transfer Protocol — created by Tim Berners-Lee (1989, public 1991). Port 80 (HTTP), 443 (HTTPS). HTTP fits strictly on Layer 7.

HTTP Details

  • All HTTP messages have headers; many also have a payload separated from the header by a blank line.
  • Each header line must be followed by CR (\r, ASCII 13) and LF (\n, ASCII 10) — i.e. \r\n.
  • A server only MUST support GET and HEAD; other methods are optional.
  • HTTP is used by web browsers, WAP browsers, and applications downloading maps/music. It fits strictly on Layer 7.

Host Header & Virtual Hosting

The primary reason for the Host: header in HTTP is to enable virtual hosting — the server may host more than one website on the same IP address. It uses the Host header to determine which site to serve.

Valid HTTP/1.0 request example: GET / HTTP/1.0\r\nHost: www.up.ac.za\r\n\r\n — method must be uppercase, resource and protocol version must be included.

HTTP Statefulness — Cookies

HTTP is naturally stateless — it forgets the client the moment a request ends. Cookies maintain session state:

  1. Server → Client: sends Set-Cookie: ID=123 in the response header.
  2. Client → Server: sends Cookie: ID=123 in all subsequent request headers.

Connection Persistence

VersionBehaviour
HTTP/1.0 (Non-persistent)Opens a new TCP connection for every single object (images, scripts, HTML). Very slow due to TCP handshake overhead for each object.
HTTP/1.1 (Persistent)Default behaviour. Uses Connection: keep-alive to send multiple objects over a single TCP connection.

HTTPS

Identical to HTTP but uses TLS/SSL encryption at the transport layer and runs on port 443. Encryption occurs just above Layer 4, not at Layer 6.

CGI — Common Gateway Interface

Instead of just returning a static file, a web server can extract the path from the GET request and use it to execute a CGI program.

How a CGI program interacts with a browser (highly tested):
(i) The CGI program writes to standard output to send output to the browser.
(ii) The CGI program reads an environment variable set by the server to receive input from the browser.

HTTP POST encoding: Information submitted via POST is sent as key-value pairs, with spaces replaced by + and URL-encoding applied.

2.6 Other Application Layer Protocols

ProtocolPurpose & Notes
TFTP (Trivial FTP)Very simple file retrieval protocol. Used by diskless computers to transfer an OS image from a server at boot time. Uses UDP (not TCP).
NTPNetwork Time Protocol — synchronises clocks; handles propagation delay to estimate true current time.
VoIP / SIPSIP (Session Initiation Protocol) establishes and terminates network-based telephone calls.
SMB / SambaServer Message Block — mounts remote file systems. Samba is the server commonly used on Unix systems to share files with Windows clients.
NFSNetwork File System — mount remote file systems on Unix environments.
RTSPReal Time Streaming Protocol — stream multimedia (e.g. Internet radio).
X.11Window system — displays graphical interfaces on a remote display. If user S is using server S from workstation W, the protocol used to transfer images is X.11. Usually tunnelled via SSH.

2.7 Sniffing Traffic

Network sniffing = capturing and inspecting raw network traffic. Best tool: Wireshark.

  • Wireshark is a popular application used to inspect traffic that flows on a network.
  • It captures packets at Layer 2. Viewing a Layer 2 frame lets you see the IP (L3), TCP/UDP (L4), and eventually the cleartext application payload (L7).
  • Ethernet switches normally only send traffic to the intended recipient — limiting what you can sniff.
  • Most modern traffic is encrypted (HTTPS) — use unencrypted protocols on a private test network for learning.
Legal concern: Be careful about the legality of capturing traffic even on your own network interface.

⚠ Exam Traps

SMTP 250 code: After a successful EHLO/HELO, the server returns condition code 250. Server-to-server SMTP uses port 25. Submission (user to first MTA) uses port 587.
IMAP vs POP3: IMAP4 manipulates mailboxes on the server. POP3 downloads to the local machine. IMAP supports complex folders and flags; POP3 does not.
TFTP uses UDP — not TCP. It is used for diskless boot (OS image transfer), not general file transfer (that's FTP).
CGI mechanics: CGI writes to stdout to send to browser; reads an environment variable set by the server to receive input. These specific mechanics are frequently tested.
Telnet escape character: Ctrl+] opens the Telnet client console. This is called the escape character.

Memo / Answer Key

MCQ Answers

A1. B (Dæmon).
A2. A (IMAP4 — it is specifically designed to manipulate a mailbox on a server).
A3. C (250 — standard SMTP success code for HELO/EHLO).
A4. C (Virtual terminal).
A5. C (telnet www.example.com 80 — HTTP runs on port 80).
A6. A (data, passive — the data channel is the problem; passive mode inverts who connects).
A7. E (Writes to standard output; reads an environment variable set by the server).
A8. A (Client-server).
A9. E (Wireshark).
A10. B (RICA).
A11. C (Full stop on a line of its own).
A12. C (Virtual hosting — the server may host more than one site on the same IP).

Long-Form Answers

A13. Telnet session.

  • a) Virtual terminal
  • b) 23
  • c) localecho
  • d) telnet www.example.com 80
  • e) Escape character (often ^])

A14. SMTP exchange.

  • a) rcpt to: u@xx.co.za (or whatever address)
  • b) A blank line separates the header from the body.
  • c) A full stop on a line of its own (.)
  • d) The problem: if the email body itself contains a line with only a full stop, SMTP treats it as end-of-message, truncating the body prematurely. Modern clients use dot-stuffing — inserting an extra dot before any line that starts with a dot — so a body line of . becomes .. on the wire, and the extra dot is stripped at the destination.
